# 玩法理解与画面设计

## 类型判断

本作属于“发射 / 飞行 + 局外成长”小游戏，与 Learn to Fly、Into Space 一类作品共享基本循环：准备改装 → 短程试飞 → 承担风险换资源 → 结算 → 再次尝试。这里是基于类型玩法的设计分析，没有声称进行外部用户研究或最新竞品调研。

短期目标是捡到资源并突破本局高度；中期目标是解锁材料、外观和脉冲；长期目标是从木椅抵达太空。失败仍提供成长资源，因此反馈要强调“这次又向前了一点”，而非只有失败惩罚。当前经济直接按高度放大奖励，后期收益较快；本次保持原数值，没有宣称完成经济平衡。

## 设计重点与本次实现

| 玩家需要感受到什么 | 实现方式 |
| --- | --- |
| 点火是一个明确动作 | 保留蓄力进度条，加入立体喷口、闪动喷焰和暖色引擎灯 |
| 升级让设备发生变化 | 木椅与万户人物、机翼与螺旋桨、多联火箭、环形未来飞行器；外观随原有等级条件变化 |
| 正在快速上升 | 多层云、前景速度线、受控横向倾斜、发射台和山地后退 |
| 高度带来新的世界 | 晨曦渐变天空逐步过渡到星空、极光光带和装饰性行星 |
| 奖励值得靠近 | 金属金币旋转、晶石切面、拾取粒子；资源中心保持原碰撞坐标 |
| 危险可以辨认 | 立体鸟翼、带闪电的雷云、陨石、太阳能板卫星和碎片，轮廓与资源区分 |
| 能力有明确反馈 | 单次脉冲拉长喷焰，音速护盾显示透明保护体和发光环 |

整体采用深青色实验室界面、暖金色资源和低多边形场景，保留“古代木椅向科幻星海演进”的反差。桌面左右分栏，手机上下排列。地图和行星服务于幻想氛围，不是物理轨道或真实天体位置模拟。

## 渲染与玩法边界

游戏仍是原有平面操作，Three.js 提供立体画面，并未改成自由视角 3D。正交相机使用与原玩法相同的 390 × 720 坐标系，拾取物和障碍中心逐帧同步到对应世界位置，避免为了镜头效果改变操作判断。3D 载具按类别呈现视觉包络，碰撞仍使用原半径，并非按三角面精确判定。

`game.js` 在更新状态后向 `scene.render()` 传入只读使用的游戏对象、能力与外观；场景不改动金币、等级、碰撞或奖励。2D Canvas 负责文字、里程碑、操作提示和结算遮罩。WebGL 不可用时使用完整的旧版渲染，游戏流程继续运行。

保留原有升级上限、解锁条件和奖励公式。只同步修正了与实际操作不符的“持续点火”说明和“脉冲冷却中”提示，并补充指针捕获、触点丢失与窗口失焦时的输入释放处理。

## 性能与限制

- 复用几何体和材质，按类型回收活动物体；拾取与碰撞仍只由原游戏循环决定。
- 粒子采用固定容量 BufferGeometry，速度线使用一个 LineSegments；设备像素比封顶 1.75。
- 使用实时光照、发光材质和透明环，不使用高开销全屏 Bloom，不加载外部素材。
- 支持减少动态效果和 2D 备用模式。无头 Chromium 已验证功能，真实手机的温度、帧率和功耗仍需真机检查。
- 外观共 20 个等级，但按飞行器类别复用结构，部分等级通过规模、颜色和环形结构区分；并非 20 套独立美术资产。
- Three.js 增加了首包体积；当前构建约 621 KB JavaScript、gzip 约 161 KB，Vite 的 500 KB 分块提醒是已知结果，构建正常通过。

## 后续可独立安排的工作

优先进行真机操作与性能观察，再决定是否增加画质选择；之后可分别安排音效、里程碑奖励、后期经济节奏和更细分的外观设计。这些工作不属于本次画面增强的完成条件。
